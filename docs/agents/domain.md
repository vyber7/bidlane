# Domain docs

Bidlane uses a single-context layout. The root `GLOSSARY.md` defines domain terms, and `docs/adr/` holds architecture decision records.

## Before exploring

Read the glossary and any ADRs relevant to the area you're working in. If either location is absent, continue. The domain-modeling workflow creates these files when the team settles terms or records decisions.

## Use the domain vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names. If a term is missing, check how the project names the concept and bring genuine gaps to `/domain-modeling`.

If a proposal conflicts with an ADR, cite the decision and explain why it may be worth reopening.
